How a request travels

Scroll through the steps. The diagram builds up one frame at a time, and whatever is new in each step is drawn in blue.

The browser asks

The user clicks a link. The browser resolves the domain and sends a GET request towards the site.

The CDN checks its cache

The nearest edge node looks for a cached copy. On a hit it answers straight away, and the origin never hears about it. This time it's a miss.

The origin does the work

The request continues to the app server, which queries the database and renders the response.

The response flows back

The CDN stores the response with a Cache-Control lifetime, then hands it to the browser. The next visitor gets a hit.

Behind it

In a real Code Hike setup, each ## !!steps block in the MDX pairs a bit of prose with one Excalidraw frame exported as an SVG.

  • Code Hike parses the steps and tracks which one is selected as you scroll.
  • Each frame is a copy of the previous one with a few additions, so unchanged parts stay in place.
  • This page draws the frames live with Rough.js, the library behind Excalidraw's hand-drawn look.
